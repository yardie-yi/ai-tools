对比条件与局限

  • 两组使用同一任务、固定材料、同一写作模型与 medium 推理档位。要求恰好四步、约 300–450 个汉字，准确保留安装与激活要点。
  • 每次独立执行，交替顺序减少固定先后偏差。本次 CLI 禁用插件、关闭用户配置加载和联网搜索，并通过临时 provider 参数固定 HTTPS；不改变用户配置文件。
  • 两端先做了单独连通性测试，不计入三轮成绩。没有主动启用客户端响应缓存；服务端缓存、排队、网络和后台负载无法完全控制，返回的 token 信息保留在原始 JSON。
  • B 改变的是输入资料的筛选流程，不能据此声称“TypeSafe 提升了同一模型的逐 token 生成速度”。最终输出长度与内容差异也会影响结果。
  • 样本仅三对、主题仅 Ponytail 简短指南；没有完整重跑此前含搜索、设计、HTML 编写与浏览器验证的任务。
  • 正式运行未记录额外工具调用或网络回退错误；两组均出现技能描述缩短的元数据提示。CLI 固定上下文仍占较多输入 token，详见每次 usage。
  • 未估算费用：返回 token 用量已保留，但不同服务的实际账户费率与 Codex 订阅计量不能直接相加比较。
