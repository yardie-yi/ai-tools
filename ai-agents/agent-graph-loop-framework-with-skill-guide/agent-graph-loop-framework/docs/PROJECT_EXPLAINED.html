01 / CONCEPT

它是什么

它不是常驻进程。Agent 在你打开的项目里读取协议文件，然后使用文件系统、Shell、Git 和测试工具完成任务。

一句话：Graph 管路线；Loop 管迭代；Skill 管可复用的项目化方法；.evospec 管真实项目参数；Harness 是 Agent 的工具和执行环境。
ENTRY

入口与边界

AGENTS.md；Claude Code 另读 CLAUDE.md。普通问答不必加载全部协议。

GRAPH

选择任务路线

router.yaml 指向开发、Bug、审查、问答等 Graph，定义权限和停止条件。

LOOP

小步闭环

观察 → 决定 → 行动 → 验证。失败时基于新证据修正。

SKILL · OPTIONAL

项目专有方法

model-skill 是轻量索引；仅当任务要用配置驱动的构建、推板、记录等流程时加载。

PROJECT DATA

真实配置

project.yaml 管门禁；module.config.yaml 管路径、命令、目标和规则。

EVIDENCE

结果与状态

命令退出码和相关测试是证据。run state 只用于需要跨阶段恢复的任务。

02 / RUNTIME

它怎样运行

① 用户目标解释、实现、修复、构建或审查
② 入口 / Graph简单任务直接做；复杂任务选路线
③ Node / Loop行动、定向验证、根据证据修正
④ Skill（可选）只读当前 reference 与相关配置
⑤ 结果 / 证据交付改动、检查结果与剩余风险

Graph/Loop 是 Agent 遵循的 Markdown/YAML 协议，不由后台调度器自动执行；Skill 也不是每次任务的必经站。

按影响验证

代码解释只读相关文件；行为变更运行相关测试；构建或集成受影响时运行相应构建。无需例行执行全套 build/test/review。

按风险升级

高风险或跨模块任务可用独立只读 Reviewer。部署、push、远端删除/覆盖和停止远端进程需要针对具体目标的明确授权。

03 / CHECK

先在模板目录验证什么

下面检查协议与配置格式；它不会启动 Agent 服务，也不代表业务项目已构建成功。

python3 scripts/validate-skills.py
python3 scripts/validate-framework.py
python3 scripts/validate-evospec.py
当前 .evospec 仍有模板占位符，最后一条可返回 WARN。接入项目并填写准备使用的配置后，才按需运行 python3 scripts/validate-evospec.py --strict。不要执行未解析的 REQUIRED 命令或目标。

只有长任务需要恢复时才运行 python3 scripts/new-run.py "任务名称"；它会写入 .agent/runs/，不是每次任务的启动命令。业务构建/测试包装器需先核对 project-commands.sh。

04 / ADOPTION

如何在项目中使用

复制必要目录

将 AGENTS.md、.agent/、scripts/ 放到目标仓库根目录；用项目专有流程时再复制 .evospec/。按工具保留对应平台适配目录。

填写项目事实

在 .agent/project.yaml 设置项目名、风险与门禁；在 .evospec/module.config.yaml 只填准备使用的能力。未知设备、服务器、分支和凭据不能猜。

校准命令与规则

确认 scripts/project-commands.sh 的构建、测试、lint 命令；审阅 .evospec/rules/INDEX.md 的适用性，然后运行静态检查。

在目标仓库向 Agent 提任务

日常用自然语言即可。需要配置驱动的构建、推板或记录时再选 model-skill route；检查实际证据，远端动作单独授权。

常见误解准确理解
Graph = LangGraph？不是。这里是协议文件；接入 LangGraph 是额外实现。
每次都要多 Agent、全量测试？不需要。职责拆分与验证范围由风险、影响和证据决定。
Jev 会自动进入框架？不会。全局 Jev Skill 可以独立使用，不必注册到本项目。
