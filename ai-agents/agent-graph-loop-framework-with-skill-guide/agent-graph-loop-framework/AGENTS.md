# Project Agent Instructions

本仓库用 `.agent/` 描述任务 Graph、局部 Loop 和可选的项目 Skill；`.evospec/` 保存项目参数与规则。这些文件是按需使用的导航，不是每次任务都要走完的清单。

## 选择任务路径

- 从用户目标和当前证据出发。任务需要分阶段或涉及权限边界时，参考 `.agent/router.yaml` 和相应的 `.agent/graphs/*.graph.md`；简单问答、局部文档或小范围修改无需先读完整协议。
- 只打开当前问题相关的源码、配置、Graph 节点、Loop 和规则；不要预先扫描全库、读取所有 Skill 或建立完整仓库地图。
- 只有任务需要 `.evospec` 支持的项目专有流程时才加载 `.agent/skills/registry.yaml` 和对应 Skill/reference。普通代码解释或局部修改不因属于某个 Graph 就自动触发 `model-skill`。
- 多阶段、可恢复的工作可用 `.agent/runs/` 记录决策和证据；短任务不必创建 run state。状态是工作记录，不能代替真实的命令结果。

## 执行与验证

- 用户要求实现或修复时，可在授权范围内直接修改本地文件、运行已确认安全的本地检查并修复由本次改动造成的失败，无需每一步重新请求许可。完成可验证的结果后再交付，不在第一版实现后无故停下。
- 先确认命令的目标、环境和副作用；模板中的自动检测命令不等于当前项目的真实构建方式。`REQUIRED`、`PLACEHOLDER`、`TODO_CONFIG`、空命令和未确认目标不得执行。
- 按改动风险选最小有意义的验证：文档检查相关链接或示例；局部逻辑运行相关测试；接口、构建配置、跨模块或高风险变更扩大到受影响的构建与回归。不要例行运行全量测试或 `scripts/verify.sh`。
- 本地测试或构建若已确认不访问生产、不会删除用户数据或触发部署，可直接运行并重试相关失败。缺少工具链、硬件或外部服务时，完成仍可安全完成的部分，并明确未验证范围；不得把未运行写成 PASS。
- 对安全关键、跨模块或难以独立判断的改动，使用只读 Reviewer；普通低风险修改可由实施者自检，不强制启动 fresh Agent。失败后先根据新证据修正；仅在反复无进展或结构性判断错误时参考 `.agent/refresh-policy.yaml`。

## 权限与证据

- `qa`、`requirement`、`review` 默认只读；用户要求修改时才进入相应写入任务。保留用户已有改动，不做无关重构，不削弱测试以制造通过。
- 部署、push、目标端删除、停止远端进程、覆盖远端文件、发布及修改凭据，需要用户对具体目标明确授权；可先做静态检查或 dry-run。普通本地编辑、定位、已确认安全的构建和相关测试不在此列。提交 commit 仅在用户要求提交时执行。
- 以源码、需求、可复现行为和实际命令输出为证据；Agent 的自述、填入 run state 的状态和 Reviewer 意见都不能覆盖失败的确定性检查。不要记录或泄露密钥。

## 完成标准

完成意味着用户请求的结果已交付，相关验证已通过或未验证风险已明确说明，没有遗留的已知相关失败。最终简要报告改动、验证范围与结果、剩余风险或阻塞；只有实际使用了 Graph、Skill、Reviewer 或 run state 时才报告它们。不要为了填满流程字段继续执行无关步骤。
