# 旧项目：同步现有 UI 布局

## 适用条件

目标页面已有可维护的 XML 或等价布局源码。现有页面树、控件名称、类型、父子关系、代码查找和业务绑定是工程事实的主要来源。

## 映射方向

先从代码确定控件，再去设计页寻找对应视觉元素：

1. 解析目标 XML，列出页面、容器、控件、坐标、尺寸和资源。
2. 搜索控件初始化、查找、状态设置、主题切换及运行时位置覆盖。
3. 结合视觉形状、父容器、相邻元素、资源尺寸、主题和分辨率，在设计页定位对应元素。
4. 建立 `现有控件 → 设计元素 → 证据 → 修改项` 映射。
5. 映射不能唯一确定时，列出候选并让用户确认，不按名称或外观猜测。

## 修改原则

- 坐标和尺寸：按设计绝对坐标计算父容器局部坐标；如果运行时代码覆盖 XML，同步修改实际生效位置。
- 切图更换：下载设计页原始资源，遵循项目已有主题、分辨率、格式、命名和打包机制。
- 新增控件：只在用户要求或开发已明确控件定义时新增。先确定类型、名称、父控件、资源和初始化入口；只补齐所需初始化和状态设置能力，不擅自接入业务信号。
- 删除控件：先搜索 XML、代码、资源表和生成规则中的引用；删除用户确认的目标及必要引用，避免留下失效查找或资源记录。
- 保持未涉及控件的名称、层级、属性、资源和代码不变，使用最小差异完成同步。

设计稿新增或缺少某个图层，并不自动等于工程中应新增或删除控件。控件增删由用户需求和开发定义决定。

## 验证

- 修改后 XML 可解析，控件名称和代码查找一致；
- 坐标换算包含父容器偏移，最终显示位置与设计一致；
- 新资源格式、像素尺寸、哈希、主题和分辨率目录正确；
- 被删除控件没有残留引用；
- 差异只包含映射中列出的控件、资源和必要代码；
- 若专有二进制尚未生成，明确标记为待执行，不能声称目标设备已更新。
