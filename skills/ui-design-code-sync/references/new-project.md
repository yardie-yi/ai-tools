# 新项目：首次生成 UI 布局

## 适用条件

目标页面没有可维护的 XML 或等价布局源码。设计页可以生成候选布局，但不能替开发工程师决定业务控件和业务逻辑。

## 前置确认

开始生成前必须确定：

- 目标 UI 引擎及版本；
- 项目分辨率、缩放规则、坐标原点和安全区域；
- XML schema、可编译的示例页面或官方模板；
- 资源格式、命名、目录和打包规则；
- 要生成的设计页面范围；
- 开发已明确的页面、控件、名称、类型、父子关系和状态要求。

缺少 UI 引擎 schema 或可用样例时，先让用户指定正确工程或模板，不能发明 XML 语法。开发尚未定义控件语义时，可以生成带稳定临时标识的视觉候选节点，但必须明确标为待确认。

## 生成流程

1. 获取页面画布尺寸、背景、可导出切图、文字、坐标、尺寸、层级、裁剪关系和主题变体。
2. 区分视觉分组与真正容器。图层组不自动等于 UI 容器，重复装饰不自动等于可交互控件。
3. 按项目 schema 生成候选页面树：
   - 页面和根容器使用项目约定；
   - 已由开发定义的控件直接采用其名称和类型；
   - 未定义业务语义的元素只生成候选图片、文本或容器节点；
   - 坐标换算为相对父容器的局部坐标；
   - 昼夜或状态切图按项目现有资源机制组织。
4. 下载原始切图，记录来源 URL、原始名、尺寸、格式和哈希。不要把整页截图切割成资源。
5. 输出候选 XML、资源清单和逐项映射，不立即接入业务信号。

## 人工确认门槛

在写入正式页面、覆盖工程文件或接入生成链之前，向用户展示一个具体可审查结果，至少包含：

- 设计页面到候选工程页面的映射；
- 控件名称、类型、父控件、坐标、尺寸和资源；
- 哪些项由开发定义，哪些项由设计推断；
- 未确定项、重叠项和可能被运行时代码覆盖的项；
- 将新增或修改的文件。

用户确认该候选结果后再集成到项目。用户提出修正时先更新候选映射，再落库。

## 验证

- XML 能被目标 UI 引擎或项目解析器接受；
- 页面尺寸、父子层级和局部坐标换算正确；
- 所有资源可找到，格式和尺寸符合工程规则；
- 设计与渲染对比在约定容差内；
- 没有凭设计图层自行加入业务逻辑。
