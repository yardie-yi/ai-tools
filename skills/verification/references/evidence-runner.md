# 本地命令证据采集器

`scripts/record_check.py` 使用 Python 3 标准库执行一个 argv 命令，保留实际结果。路径从本 Skill 所在目录解析；无需新增 Python 包。

```bash
python3 /absolute/path/to/verification/scripts/record_check.py \
  --out /absolute/path/to/evidence/new-run \
  --cwd /absolute/path/to/project \
  --input path/to/relevant-source \
  --input path/to/acceptance-test \
  -- python3 -B -m unittest -v test_module
```

这是调用模式，使用前替换为项目真实路径和已确认命令。实际参数以 `--help` 为准。`--out` 的父目录须存在，目标目录须是全新的，防止覆盖失败证据；可放在项目指定产物目录。`--input` 可重复，输入相对 `--cwd`，输出路径相对调用目录。输入须为可读普通文件，缺失会在执行命令前拒绝。

## 输出与判定

- `result.json`：完整 argv、cwd、UTC 起止时间、耗时、子进程退出码、命令状态、是否中断、输入执行前后 SHA-256、日志路径/字节数/SHA-256。
- `stdout.log` / `stderr.log`：完整字节流，直接写文件，不经截断后再保存。原始终端显示由调用者按需读取。
- 正常子进程退出码透传；启动失败返回 127，中断返回 130，采集器参数或保存错误返回 2。目录创建后发生采集错误可能只保留部分文件，应按实际错误处理。

读 `result.json` 和关键日志，再对照验收条件判定 `PASS/FAIL/BLOCKED/NOT RUN`。`command_succeeded` 仅表示命令以 0 退出，不保证测试数量、业务正确、输入未变或全链路通过；反之，有意执行的坏样本返回非 0 可能正是验证器能检测错误的证据。

若输入指纹不同/缺失，说明其在前后两个采样点不同或不可读；重新绑定证据版本并按需要复测。两次相同也不能证明期间从未修改。仅指定文件被采集，不自动证明整个工作区、依赖或运行实例的身份；按任务补充实际 revision、配置与产物身份。

## 使用边界

命令以 `shell=False` 执行；管道、重定向和变量展开不是内建语法。确需 shell 时明确传入 shell 与完整脚本，并自行正确引用参数和保留管道退出码。记录器没有权限沙箱，执行前仍须确认命令属于当前任务授权。

它不记录整个环境，不自动脱敏参数和命令输出。使用不含秘密的参数；输出目录/文件采用私有权限，分享前检查。哈希用于比对完整性，不是签名或防伪证明。

记录器会等命令结束，没有默认超时，也不管理完整进程树。只用于预期会结束的检查；长驻服务用项目现有启动/停止工具。Ctrl-C 会终止并等待直接子进程，但不能保证清理自行分离的后代或远端工作；SIGKILL、断电等可能只留下部分证据。只清理本次创建的资源，保留证据文件。

## 修改记录器后验证

在 Skill 目录运行：

```bash
python3 -B -m unittest discover -s scripts -p test_record_check.py -v
```

测试使用隔离临时目录和真实子进程，覆盖成功、失败、启动错误、拒绝覆盖、字面参数、输入变化/删除/链接改指向、大日志、权限与中断。部分权限和信号检查仅在 POSIX 平台运行；未运行的测试不能计为该平台已验证。
