# 工程验证

## 代码与服务

从仓库声明的测试/构建入口确认实际命令、目标和依赖，不凭语言猜命令。按改动风险组合：目标回归、相关边界/错误分支、类型或静态检查、构建、必要的真实运行路径。测试数量为 0、整组 skip、只 mock 到边界之前，都要说明其覆盖空缺。

测试预期从契约、独立计算或已知可信样本导出。修复失败测试时先确认是实现错误、测试错误还是环境问题；仅为了让结果变绿而删断言、放宽容差、改快照会使证明失效。快照变化需要可解释的产品行为依据。

后台任务须取得最终状态或已验证的稳定运行状态；“已启动”与“操作已完成”分开。异步接口的“返回 0/成功入队”只支持接收或入队结论，需沿消费者、插件、对端响应到约定终态核验。构建完成后检查产物存在、目标架构、路径与身份。启用管道时保留真实被测命令的退出码，例如 shell 支持时用 `set -o pipefail`；避免 `tee`、`|| true` 或截断输出掩盖失败。

## 嵌入式、协议与生成链路

先从当前项目的持久文档读取硬件型号/连接方式、工具链、构建目标、字节序、单位、边界、有效性、时序及接口声明。缺失或冲突时保留未知项，不从其他项目聊天猜参数。

按本次范围维护证据链：

`源协议版本/行 → XLSX/CSV/头文件 → 生成器与参数 → 生成代码 → 编译目标/二进制 → 设备加载身份 → 输入与可观察响应`

只要求任务覆盖的阶段，但每个阶段分别给状态。协议变更检查标识/类型/位宽/枚举/单位一致、缺失值与非法值、生成确定性及相关调用方；接口文档核对原始声明、参数、返回语义与示例可编译性。验证不能自行扩大到刷机或控制真实车辆。

主机测试、交叉编译、模拟器与真实板端分别标识。交叉编译通过不能证明加载成功；设备上的旧二进制运行正常不能证明新版本。若本次要求板端行为但板卡不可达，保留已通过的主机证据并将板端项标为 `BLOCKED`。

日志排查先校准来源时钟、时区、重启/会话边界与采集缺口，再关联请求、响应和状态转换。先检查返回码和原始值有效性；读取失败后打印的初始值、缺失值和缓存旧值不能作为成功测量。错误附近的时间相关性只支持假设；因果结论要用代码路径、协议事件或可复现干预补强，区分观察、推断和已验证根因。

## UI 与运行时

前端/Electron 用浏览器、CDP 或现有控制工具实际触发用户路径；原生应用用可用的自动化或模拟器。先确认页面/进程对应当前构建。交互语义、返回数据和持久状态用 DOM、可访问性树、网络响应或回读检查；布局、遮挡、字体和视觉变化再查看截图。

截图证明当时可见状态，不能单独证明保存成功、完整数据正确或错误恢复。有必要时重载/重启再回读。以当前授权管理登录；登录墙、MFA、验证码或缺少账号权限作为明确阻塞。

## 性能

先声明指标与测量方式，再以同设备、构建模式、输入规模、网络/缓存条件测前后结果。覆盖冷/热启动等相关条件，使用足以观察波动的重复测量，报告样本数、中心值和分散程度（如中位数及范围）。记录 trace/profile/原始样本与命令；并行采样要考虑共享资源争用。

没有基线只报告当前值；差异落在噪声范围时报告未确认改善。可量化优化同时检查结果等价性和关联功能回归。更快的单次运行、代码更短或作者的倍率宣称都不是性能提升证据。
