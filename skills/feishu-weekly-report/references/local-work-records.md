# 本地工作记录的发现与核实

每次收集本地工作记录时读取本文件。目标是覆盖可发现的工作来源，并取得本期本人工作的证据；详细检索结果用于内部整理，填报仍遵循主流程的简洁规则。

## 1. 先发现来源，再读取本期内容

### 最低必查清单

每轮先建立来源检查表，再提取事项。以下来源必须逐项给出“已读取 / 本期无记录 / 未安装或未发现 / 不可访问 / 格式不支持”的状态，不能因为当前工作目录里没有对应文件就省略：

1. **Codex 对话与任务**：检查 Codex App/CLI 可访问的任务列表、会话摘要、完整对话及工具执行结果；按本期时间、项目路径、项目名和问题编号筛选，必要时读取关联任务或归档任务。
2. **Pi 对话与任务**：检查 Pi 的会话历史、任务记录、插件/Agent 运行结果及其引用的项目路径；使用本机实际安装位置和原生历史索引，不把工具安装日志当作项目成果。
3. **Claude / Claude Code 对话与任务**：检查本期会话、项目历史、工具调用结果及其引用的仓库和产物；区分建议、未执行方案和已经验证的结果。
4. **Git 仓库**：枚举当前工作区、已配置项目目录、上述对话中出现的项目路径以及历史来源清单中的仓库。对每个本期相关仓库检查本地各分支和 worktree 的本人提交、已有远程跟踪引用、暂存/未暂存修改，以及相关未跟踪文档或交付文件；读取差异与任务上下文确认实际成果。

继续检查本机发现的其他 AI/Agent 或开发工具，例如 Cursor、Trae 及新增工具。名称只用于确保常见来源不漏查，实际路径和读取方式以当前环境为准。优先使用产品自身的任务/会话索引或只读接口；需要读取本地存储时，先定位元数据和本期候选，再定向读取内容。

- 从当前工作区、已确认项目路径和历史来源清单开始；检查当前用户目录、应用数据目录、桌面、文档及常用工作目录的目录名和文件索引，发现新增工具、项目和笔记库。下载目录仅按项目名、问题编号或已知交付文件查找。
- 同时发现 AI/Agent 工具、普通编辑器/IDE、笔记与任务工具、代码仓库、文档及日志目录。产品示例不是白名单；根据本机实际目录和可用读取能力识别来源。
- 使用文件列表、类型、时间及项目关键词缩小候选，再读取内容。优先 `rg --files`，只在相关目录补查隐藏或被忽略的记录；跳过依赖包、工具安装包和无关缓存。针对已知测试输出或交付目录单独读取，避免全盘递归全文搜索。
- 从记录中的项目路径继续定位其他工作区、仓库和相关资料。路径不在当前工作区也可读取当前用户可访问的工作记录；远端服务器或云端专有记录只登记缺口，不将本地发现自动扩展为远程登录。
- 建立来源清单：来源类型、实际路径、项目线索、可用读取方式、覆盖时间、检查结果。区分“已检查但本期无记录”“不可访问”“格式暂不支持”和“尚未检查”，不能将读取失败当作没有工作。

## 2. 按来源提取可验证的工作

| 来源 | 查找内容 | 证据使用方式 |
| --- | --- | --- |
| AI、Agent 与编辑器记录 | Codex、Pi、Claude/Claude Code 及其他已发现工具的会话、任务历史、操作结果、导出归档、IDE 本地历史 | 提取实际执行及最终结果；建议、计划、生成草稿和工具成功结果分别判断。对话中引用的仓库、日志、文档和远端任务继续加入来源清单。 |
| 代码与配置变更 | Git 各本地分支、worktree 及已有远程跟踪引用中的本期提交、工作树修改、补丁、评审导出 | 按作者及任务上下文确认归属，读取相关差异；本地提交不能证明已推送、合入或发布，工作树修改不能仅凭当前修改时间认定为本周工作。 |
| 需求、设计与技术文档 | 需求说明、接口协议、方案、评审意见、图纸、表格及版本记录 | 识别本期新增或修改内容；现有文件、下载副本或模板不能直接算作本人产出。 |
| 问题排查与技术支持 | 问题单导出、分析笔记、故障日志、复现记录、客户或同事支持记录 | 区分收到问题、复现、分析、提出方案、修复和验证；日志中的故障时间不等于用户排查时间。 |
| 测试、构建与联调 | 测试报告、构建日志、运行结果、串口/设备日志、实验记录 | 核对时间、代码版本、设备或环境及结果；区分主机测试、目标板测试与现场验证。 |
| 发布、交付与运维 | 版本说明、交付清单、部署记录、发布回执、配置变更记录 | 区分打包、准备交付、实际部署和验收；仅有安装包或构建产物不能证明交付成功。 |
| 任务与日常协作 | TODO、工作日记、个人笔记库、会议纪要、日历/邮件/工单的本地导出 | 提取本人完成事项、决策、协调、评审和跟进；计划、参会邀请和任务分配不能证明已执行。 |
| 本地终端或脚本执行记录 | 已知项目的带时间运行日志、保存的命令结果 | 仅在需要补证时定向读取，命令出现只证明尝试过；实际成功须结合退出结果或产物。 |

读取格式以实际可用工具为准：文本、Markdown、JSON/JSONL、CSV 可直接解析；数据库使用只读方式；文档、表格、PDF 用相应读取工具。大型日志按时间、问题编号和结果定位片段。二进制或无法解析的内容记录缺口，不猜测。读取期间不修改源文件、执行历史命令或为了证明结果重新运行构建、测试、部署。

仅定向读取已发现的相关终端记录，避免整份输出全局 shell 历史。认证文件、环境密钥、密码库和无关私人内容不进入检索材料；记录中意外出现的凭据不保留在证据摘要或填报中。

## 3. 对齐日期、本人归属和最终状态

- 以周报实际日期和用户时区为准。优先使用事件时间、提交时间、任务完成时间及文档修订记录；文件修改时间仅用于筛选候选，复制、解压或同步可能改变它。
- Git 作者身份结合仓库配置、用户已知姓名/邮箱及会话上下文确认，不能仅按当前系统用户名过滤，也不能将合并进来的团队提交算作本人工作。未提交修改需要本期编辑记录或其他上下文佐证，避免把长期遗留改动计入本周。
- 本期活动允许引用更早的背景材料，但只汇总本期进展；旧任务本周有新验证、新结论或新交付时，写新增进展。
- 共享文档和团队记录只提取有证据属于本人的贡献。自动生成文件、批量格式化、机器人提交及例行自动构建不单独充当工作成果，结合本人触发、处理或验收活动判断。
- 用项目、问题编号、功能及产出关联同一事项，将 AI 会话、提交、日志和笔记合并成一条工作项；复制目录、多个 worktree、重复导出及同一补丁的不同提交去重。
- 状态以最近的可靠证据为准。出现回退、测试失败或后续反证时修正结论；重要矛盾无法消除则保留待确认状态。主要成果尽量由实际变更、报告或交付记录佐证，只有本人叙述时按其可支持的程度表述。

## 4. 重复调用时增量读取

在当前账号配置对应的本地私有目录保存来源索引与本期证据摘要：实际路径、来源标识、项目、事件时间、读取进度及必要的文件指纹。只保存追溯和去重需要的摘要，不复制完整会话、终端历史或日志。

每次先检查来源目录和新增项目，再读取变化的来源。文件时间/大小/指纹用于判断是否需要重读，工作日期仍按内容判断；重读本期的活动会话和近期重叠时间段，捕获补写、状态更新、轮转及迟到记录。变化来源按稳定记录 ID 去重；文件被截断、替换或索引失效时重新读取受影响的本期范围。

将新增证据合并进本期完整事项集合后再生成填报，保留先前已证实的本期成果；不能用本次增量内容覆盖掉其他本期工作。换周后按新周期重新筛选，跨周事项仅延续本期实际进展。

完成条件：Codex、Pi、Claude/Claude Code、每个本期相关 Git 仓库以及其他已发现来源都有明确检查结果，拟填事项均可定位到本期本人工作的证据。若有影响完整性的来源缺口，简短说明；不宣称已读取本机全部历史。来源多寡、提交数、代码行数、消息数和会话时长均不能直接换算工时。
