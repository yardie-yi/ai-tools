# 周报模板核对与模块化写法

每次生成或更新周报前读取本文件。以用户最新明确要求为准，结合本期群通知、模板和账号已保存的确认样例；存在冲突或不明确的必要字段时，向用户说明具体差异并暂停受影响内容的写入。定时执行同样需要反馈，不能为了完成任务省略必填格式。

## 写前核对

- 确定本人目标单元格、项目与模块层级，以及列表、缩进、段落、加粗和括号标注形式。只按模板填目标内容，保持表格行列、合并、列宽、人员引用及其他人内容。
- 每条事项包含主要进展、实际状态，必要时补充阻塞或下一步；模板要求时附上 `（完成比例，N天/人）`。完成比例不等于工时表项目占比；人天标注可能是预计总量或实际投入，须按已确认口径填写，不能仅凭示例推定含义。
- 用户当期亲自填写的比例和天数可以原样复用；后续周期须用当期明确证据或用户确认更新，不能沿用旧数字充当新进展。允许估算工时表占比的授权不自动涵盖周报完成率或人天估算。
- 模板不明确、完成率或人天缺依据时，先保留有证据的工作草稿，集中反馈待确认项；模板已明确的其他事项可继续处理。写后回读同时检查内容和格式，不能只检查文字是否存在。

## 8775 模块模板：用户确认参考

模板标识：`8775-modules-v1`。以下为用户在 2026-10-29 提供的当期样例；用于已确认采用此模板的账号。其他账号仍按自己的模板。模块名和层级可以持续复用，事项、状态、比例及天数按当期更新。

- Vehicle-service
  - 与mcu联调SPI：B样硬件与mcu的spi通信失败，QNX侧已根据新原理图修改GPIO口，spi依然无数据，待mcu分析反馈后继续联调（50%，2天/人）
  - 与android联调V-SOCKET:在板端部署支持V-SOCKET通信的Vehicle-service进程，待安卓联调反馈结果（50%，2天/人）
- PowerManager
  - 已确认实现方案，编码进行中（20%，10天/人）

Vehicle-service 下按 MCU SPI、Android V-SOCKET 等实际工作分别列子项；PowerManager 单独列方案、编码、验证等进展。新事项按所属模块归类，有新模块时按当期实际补充，避免把所有8775工作压成无模块的平铺清单。CLI写入须保留此父子列表层级。

用户当期直接给出的“编码进行中”等状态可作为本人陈述；没有对应编译、测试或板端结果时，不扩写成已完成或验证通过。
