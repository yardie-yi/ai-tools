# 交付结构与字段

写摘要、指南、知识库或AGENTS入口前读取。复用用户已有布局；只创建本次需要的产物。

```text
<总结输出路径>/
  项目开发指导.md
  文档清单.md
  导航.html                              # 本次生成可视导航时；文件名沿用既有登记
  summaries/<原名>总结.md
  summaries/<稳定来源ID>/<原名>总结.md   # 同名或既有分组需要时
  verification/                         # 实际证据、失败记录、批次台账
  代码分析/                             # 范围允许且确有代码派生资料时
<项目根目录>/
  AGENTS.md
  .project-knowledge/
    INDEX.md
    sources.md
    facts.md
    access.md
```

## 唯一台账与展示页

小集合可直接用`sources.md`维护；递归批量、并行读取或断点发布时以结构化台账为权威，`sources.md`、文档清单、覆盖数、云端索引和可视页均由它派生。版本状态不在多份表中手工重复维护。

| 字段组 | 保留信息 |
| --- | --- |
| 身份 | 稳定source_id、别名、精确原名、原始URL/路径、解析后的对象/附件ID |
| 版本 | revision/更新时间/内容哈希（可得者）、读取时间、适用版本 |
| 来源链 | 初始根或其他已授权发现方式、全部父source_id、章节/块/页码/单元格 |
| 正文读取 | 已读/部分可读/未读、方法及证据位置、实际错误、已覆盖与缺失内容 |
| 引用展开 | 是否已枚举、待定位/待处理目标；正文已读但附件缺失仍保留依赖缺口 |
| 输出 | 唯一summary_path、当前摘要哈希；人工补充和上次已核验版本 |
| 共享判断 | 已知来源/目标范围、判断依据或缺失信息，独立于读取状态 |
| 云端发布（如有） | 目标ID/URL/父目录、摘要/仅入口/未完成说明模式、预期及回读revision、草稿哈希、写入/回读状态与日志 |

文档来源、资源条目和引用边分开登记。跨多个父来源的同一目标只算一份文档；流程图作为父内容、独立附件作为来源时不可双计。原文、来源别名、不同历史版本及代码派生资料分别有身份/适用依据，代码派生资料不计入发现的原始文档数。

目录或名称式引用无法定位时留候选和父位置，不猜出完整来源ID。数字/点号不是扩展名；只移除最后一个已识别格式后缀。同名来源可放`<source_id>/调试手册总结.md`，后续路径沿用登记，不根据新标题另建重复文件。

## 短摘要

默认结构可缩为下例；必要条件较多时按内容展开，不为达到篇幅目标省略关键步骤。

```markdown
# 原文档名总结

[原文](真实来源) · 版本… · 读取日期… · 已读/部分可读及具体缺口

一句用途与适用条件。

- 开发时常用的入口、命令或接口约束，紧邻来源位置。
- 关键配置/参数关系或操作顺序。
- 会影响实际使用的限制、冲突及必要前提。

[关联资料及读取状态](真实索引位置)
```

按需要提供命令块或小表。操作信息至少让读者知道在哪里、在什么条件下使用、参数如何选择、原文给出何种结果；未知且影响操作时注明未说明。不机械填满“模块/工具/账号/结果”等空字段，也不逐条翻译整篇原文。

优先缩短重复背景、完整下载列表、低频历史记录和审计过程。长命令必要时原样保留，不能删掉引号、条件分支、同步/拔盘等顺序。详版证据放`verification/`并从短摘要进入。关联项较多时链接主题索引，不堆叠同名“引用资料”URL。

未取得正文且无旧总结时，状态说明只包含原文、实际问题、影响与补齐条件，明确“未完成总结”。有旧总结时保留已核验内容及版本，增加当前无法核验提示。源码推导的说明开头注明“根据代码与文档整理，非原始设计文档”，附版本/位置/推导边界。

## 开发指南

`项目开发指导.md`靠前放**文档路由表**，按开发任务组织，不重排成长篇资料目录。常用主路由链接主题子索引，所有未排除来源均可到达。

| 任务/问题 | 何时查、能解决什么 | 原文具体位置及短摘要 | 适用范围/状态 |
| --- | --- | --- | --- |

用户要求且已有代码核验时再加代码入口，注明主机、仓库、版本和行号；不要为纯文档任务强填该列。获取代码、编译、上板、调试、配置、接口或历史故障只列有依据且本任务需要的主题。

固定保留**缺失的必要内容（文档或其他）**，集中列影响开发的未读规范、版本冲突、未验证参数、包/环境/账号/日志等必要前提。详细访问错误放台账，主指南只呈现影响和下一步。

| 缺口 | 当前证据/已查范围 | 影响及阻塞程度 | 补齐方式 |
| --- | --- | --- | --- |

区分范围内未找到、已有但不可访问、内容冲突、只有推导。未知责任人不猜；已知联系人可引用，不因此主动发消息。没有发现时写明实际核查范围，不声称整个项目没有缺口。

## 知识库与AGENTS入口

- `INDEX.md`：项目根目录、输出位置、覆盖状态，以及指向指南路由/必要缺口、短事实和来源台账的简短导航。
- `sources.md`：统一台账的可读入口。保留根集合和递归边界、初始/递归/其他已授权发现数量、正文及依赖状态，关联本地与实际云端产物。
- `facts.md`：重要约束、硬件配置、接口契约等短事实；每条附适用范围、来源位置、日期和状态。冲突并列保留，完整步骤链接摘要。
- `access.md`：分别写实际读取结果、原文要求的开发操作权限、允许输出的范围。未测试的权限标未验证；仅实际执行过ACL变更时记录前后值。

长流程只保留一处正文，多处入口链接同一份；知识库不缓存真实凭据，也不把原文中的操作身份解释为本次执行授权。云端输出采用可访问的真实URL，本地知识库采用可解析文件链接。

写入前读完整个`AGENTS.md`，已有等价入口就合并；维护一个稳定标记块，保留人工规则、原文必读与代码权威位置。缺少该文件时才创建。示例路径需替换为真实路径：

```markdown
<!-- project-doc-organizer:begin -->
## 项目知识库

开发、编译、上板调试或bug分析前，先读取[知识库索引](.project-knowledge/INDEX.md)，
再按任务查对应摘要、版本与未核验项。原文必读及本文件既有约束继续适用。
<!-- project-doc-organizer:end -->
```

目标文件不可写时交付精确待合入块和可写产物，标注接入未完成，不声称已更新。

## 整体核验与增量整理

覆盖检查针对**整个交付目录**及当前台账，不只扫描本轮临时子目录。分别检查正式摘要、仍被metadata引用的中间草稿、历史快照、归档和人工文件。无引用不等于可以删除：只有来源可追溯、确认由本任务生成且不在当前来源/发布/导航中的废弃稿才可归档；保留原路径、哈希和迁移位置。

范围、身份、路径和哈希变化需要同步来源台账、摘要、导航及发布登记。重复运行检查来源ID/别名冲突、重复摘要路径、根可达性、全部引用字段覆盖、本地链接和云端真实目录。规范化内容哈希可以辅助发现重复，但不能据此合并不同适用版本。

验证记录列出实际命令/工具、退出码/结果、前后对比和未覆盖事项。统计至少区分：唯一来源数、正文已读/部分/未读、引用未展开分支、正文摘要/仅入口/未完成说明、发布回读结果。分别报告旧失败恢复数与递归新增数，避免用变化后的总分母表达“重试失败率”。历史证据保留原时间；当前状态从最终台账生成。
