# 引用发现与代码核验

展开正文引用、附件或进行已获范围授权的代码核验时读取。所有结果回到同一来源台账；引用边与来源身份分开存储。

## 队列与身份

先解析身份和类型，再分配唯一摘要路径并入队；稳定路径在后续重试中复用。每条引用保存父来源、章节/页码/单元格、显示标题、原始链接与实际目标。队列按以下结果推进：

| 识别结果 | 处理 |
| --- | --- |
| 已有来源的新引用 | 合并父关系和别名，复用读取证据；版本变化才更新相关内容 |
| 新独立文档或附件 | 分配稳定身份，入队读取正文，随后提取其引用 |
| 父文档内部章节、图表或锚点 | 保留位置，纳入父文档完整性；独立嵌入文件另建身份 |
| 服务/API业务地址、工具包、二进制、网站导航 | 登记资源类型、用途和依据；不伪造文档摘要，不调用业务接口 |
| 只有文件名、标题或模糊图片链接 | 登记待定位及父位置；没有独立检索授权时不猜URL或搜索整个项目 |
| 暂时无法判断或读取失败 | 保留候选及实际错误，继续其他分支；不静默丢弃 |

平台稳定 ID 优先于标题或URL外形。Wiki快捷方式解析到实际对象后登记别名；同名不同身份分别保留。相对引用以原文所在位置解析。URL规范化只去掉已确认的跟踪字段与文内定位锚点；保留路由fragment、附件UUID、pageId、版本参数和签名以外的身份信息。共享一个父页面URL不代表是同一附件，普通路径中的`+`也不能任意转成空格。

无平台ID的嵌入文件可用内容哈希去重，并保存所有父关系。相同正文、不同版本或不同来源有已验证的内容一致依据时可以复用提取结果，但仍保留来源与适用版本；仅标题相同不合并。不能可靠识别的同名引用保持候选，不虚构身份。

## 发现与读取完整性

检查 Markdown/HTML链接、裸URL、文档卡片、表格富文本、脚注/参考文献、独立附件、内嵌表格/画板及图片中的资料入口。处理分页、子目录和已发现的所有引用类型，不能只消费某一个队列字段。

- **电子表格**：枚举全部sheet（含hidden/veryHidden）、隐藏行列、富文本链接、公式及缓存、Drawing/图片、嵌入文件。提取全部单元格不等于看懂所有流程连线；分别记录文字覆盖和视觉核验范围，不为读取而执行宏或重算外部连接。
- **PDF/图像/幻灯片**：检查页数、文本缺失、图表与附件；扫描页和关键流程图需要实际看图。渲染失败保留部分可读状态，不把字节下载成功计为正文已读。
- **转换预览**：记录读到的是转换PDF或图片；原Excel工作表、隐藏项和附件未取得时明确缺口。
- **归档与嵌入文件**：在隔离目录枚举、解包并保留结构。文档继续入队；脚本、密钥材料、安装/固件包等登记资源，按任务必要性只读检查，不执行或下载无关敏感材料。
- **版本差异**：可以复用可靠的相同内容，但读完差异和变化图表；记录比较覆盖，不能仅凭更新时间替代旧版。

明确引用的外部规范同样检查正文引用。原链接重定向时先读取落地页，再区分具体文档、登录壳、产品导航或失败；不能因为域名外部或标题不像本项目就排除。网站导航、广告和管理入口按实际性质登记，不递归整站；书名式引用无法定位时保留缺口。

循环引用遇到已登记身份时结束该边，不停止其他分支。每个已读来源分别记录正文覆盖和引用依赖覆盖；无法读取的来源，其下级引用仍是未知，不用固定深度上限宣称递归完成。

## 从文档查代码，再从代码找资料

仅在主流程确定需要且范围允许时执行。严格根引用范围下，代码只是核验依据，搜索命中的其他文档不自动加入总结；用户另行授权扩展时才增加独立发现来源。

1. **确认代码依据**：遵循项目规则定位权威工作树；记录实际主机与路径。每个涉及的 Git 仓库执行 `pwd`、`git rev-parse --show-toplevel`、`git branch --show-current`、`git rev-parse HEAD` 和 `git status --short`。已有改动会影响结论时记录具体文件的未提交状态，不能只引用 HEAD 冒充当前内容。非 Git 源码记录路径、时间及必要哈希。与文档/固件版本无法对齐时明确局限。
2. **建立双向检索线索**：先用 `rg --files` 查资料候选，再用 `rg -n` 搜索文档中的模块、接口名、状态名、消息常量和错误码；阅读匹配点上下文。也搜索代码里的文档标题/链接、协议生成说明及源表路径，把范围允许的新文档加入引用清单，并注明代码发现途径。仅文件名命中是候选，不等于读过或证实对应关系。
3. **找现有流程资料**：检查 Markdown/Mermaid、PlantUML、draw.io、图像、PDF、设计说明中的流程图、时序图、状态图和模块通信图。沿入口、调用链、状态迁移、回调、超时和错误分支对照实现；不要用顺序函数列表代替异步时序。图像类资料须看图，无法读取图意时标明范围。
4. **找通信交互资料**：检查协议文档、接口契约、ID 对照表、头文件枚举/宏、IDL/proto/XML/JSON/CSV 源表、生成代码说明和分发注册表；沿定义追踪发送方、接收方及处理入口。只搜索与项目技术栈相关的类型，无需为示例格式全部生成占位文件。

代码不足或无法访问时仍交付已有资料，并在缺口清单写清“代码未核验”；资料中没有提供的账号或仓库位置不自行猜测。整理阶段不切分支、不修改代码、不安装项目依赖，也不运行构建或设备命令来补证据。

## 流程与通信 ID 的证据要求

流程说明注明适用版本/配置、参与模块、触发条件、关键路径、已查到的分支/回调/超时，以及对应的原文章节和 `源码路径:行号`。静态调用关系不足以证明运行顺序；未查到的边界写“未核实”。

通信交互资料按实际协议记录：

| 字段 | 要点 |
| --- | --- |
| 名称与标识 | 保留符号名和原始值/表达式；能可靠解析时可补等价十六/十进制，不能猜枚举值 |
| 协议与作用域 | 所属总线/通道、服务、命名空间、版本/功能宏；不同作用域相同数字不直接判为冲突 |
| 交互关系 | 发送方→接收方、请求/响应/通知/回调及对应项；请求响应配对须有文档或实际调用/注册依据 |
| 定义与处理 | 定义文件、源表、发送调用、分发/处理入口和行号；无法追踪处单列 |
| 数据契约 | 已有依据的字段、单位、枚举、错误码、超时/重试等；缺失则说明影响 |
| 证据状态 | 原文描述、代码可见事实、静态推导或仍待确认；记录仓库分支/提交与未提交差异 |

不能只凭数值相邻配请求与响应，也不能把日志展示的编号直接当成线上协议值。文档与实现冲突时保留两边的适用范围、值与位置，列入必要内容缺口；不替用户选定实际目标固件。

## 原文总结与派生资料

- 找到既有流程/ID 文档时，读正文后按“原名＋总结.md”输出，并在指南路由表指向原文、总结及相关代码。
- 原文没有对应资料，而源码证据足以支撑工程使用时，可生成 `<输出路径>/代码分析/<模块>流程说明.md`、`<模块>通信交互ID对照.md` 等精简派生资料。流程适合用 Mermaid 时采用 Mermaid；内容按证据覆盖范围命名，不强求两类文件都有。
- 派生资料开头写“根据代码与文档整理，非原始设计文档”，附源码版本、文件行号、原文引用、推导条件和未核验项；它不计入原文文档数，也不套用“原名＋总结”的规则。证据不足时保留候选位置和缺口，不能补造流程或 ID。
- 缺少原始规范仍作为缺口保留，不能因生成了一张图/表就认为规范已补齐。将派生资料接入指南路由及知识库入口；增量更新同时检查代码提交、相关工作树内容和原文版本。
