# Bug 修复记录

- 日期：2026-08-11

- 代码提交关联：SWLF2-779202
- 涉及模块：蓝牙媒体状态、主界面媒体弹窗

## 问题现象

上电连接蓝牙后未播放音乐，主页面仍显示媒体弹窗。

## 复现条件

- BAT ON、IGN ON、电压 13.5 V。
- 连接手机蓝牙后进入主页面，不启动音乐播放。
- ONES 记录环境：SOC 00.01.31、MCU 00.00.69、BT 01.03.03，发生频率为偶尔。

## 根因与证据

`MediaController::musicStateData()` 原逻辑仅依据 `stateInfo.state == MUSIC_STATE_PLAY` 设置 `mMediaPlayState`，没有区分连接会话内的启动同步状态和实际播放进度。`StateController::onControlWinStatus()` 直接以该状态控制主界面媒体弹窗，因此连接同步阶段未形成实际播放进度的 `PLAY` 回调会被误认为正在播放。

蓝牙服务在 AVRCP 注册完成后会主动查询播放状态，查询响应与 HMI 回调注册存在异步时序窗口。HMI 可以通过连接会话和连续进度数据区分启动同步状态与实际播放状态，无需修改协议或 UI 布局。

## 修改点

| 文件 | 修改内容 |
|---|---|
| `awtk/awtkhmi/src/Controller/src/media/mediaController.cpp` | 跟踪连接会话，首个 `PLAY` 仅记录进度基线，后续进度向前增长后确认播放；进度回退仅重置基线；仅在状态变化时记录日志 |
| `awtk/awtkhmi/src/Controller/src/media/mediaController.h` | 增加连接会话、进度基线及跨线程互斥保护状态 |
